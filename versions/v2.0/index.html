03

API Setup: conecte a WABA e salve os IDs

A API Setup conecta seu app a uma WhatsApp Business Account. É aqui que aparecem os identificadores que seu backend usará.

WABA ID

Identifica a conta WhatsApp Business. Salve-o para operações administrativas e templates.

Phone Number ID

Identifica o número na Cloud API. É usado no endpoint de mensagens.

Test number

No onboarding inicial, a Meta fornece um número de teste para você validar o fluxo antes do número real.

.env — estrutura recomendada
GRAPH_API_VERSION=vXX.X
WHATSAPP_WABA_ID=...
WHATSAPP_PHONE_NUMBER_ID=...
WHATSAPP_ACCESS_TOKEN=...
WHATSAPP_VERIFY_TOKEN=...
META_APP_SECRET=...
Versão da Graph API: as páginas oficiais consultadas hoje exibem exemplos com versões diferentes (v23.0 e v26.0). Use uma variável e confira a versão configurada/suportada pelo seu app em vez de copiar uma versão fixa de um tutorial.

05

Enviar a primeira mensagem

Todas as mensagens são enviadas pelo endpoint do Phone Number ID. O corpo muda conforme o tipo de mensagem.

O que observar

  1. Service messages são livres dentro da janela de atendimento.
  2. O endpoint usa o Phone Number ID.
  3. A resposta de envio não prova entrega: o webhook fornece o status.
cURL — mensagem de texto durante janela de atendimento
curl "https://graph.facebook.com/${GRAPH_API_VERSION}/${WHATSAPP_PHONE_NUMBER_ID}/messages" \
  -H "Authorization: Bearer ${WHATSAPP_ACCESS_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "messaging_product": "whatsapp",
    "recipient_type": "individual",
    "to": "+55SEUNUMERO",
    "type": "text",
    "text": {
      "body": "Olá! Mensagem enviada pela Cloud API."
    }
  }'
HTTP aceito ≠ entregue. A resposta da Messages API confirma que a Meta aceitou a requisição. O status real (sent, delivered, read, failed) chega pelo webhook.
Formato do telefone: a documentação recomenda incluir + e código do país. Isso reduz risco de entrega incorreta.
06

Webhook: receber mensagens e status

O webhook tem duas responsabilidades: responder à verificação inicial por GET e receber eventos por POST. Depois, assine o campo messages.

O que observar

  1. Callback URL deve ser acessível pela Meta.
  2. Verify Token precisa bater com o valor do servidor.
  3. Depois da verificação, assine o campo messages.

Node.js / Express — verificação mínima
app.get("/webhook", (req, res) => {
  const mode = req.query["hub.mode"];
  const token = req.query["hub.verify_token"];
  const challenge = req.query["hub.challenge"];

  if (mode === "subscribe" &&
      token === process.env.WHATSAPP_VERIFY_TOKEN) {
    return res.status(200).send(challenge);
  }

  return res.sendStatus(403);
});
Node.js — valide a assinatura antes de processar POST
import crypto from "node:crypto";

function validMetaSignature(rawBody, signature) {
  const expected = "sha256=" + crypto
    .createHmac("sha256", process.env.META_APP_SECRET)
    .update(rawBody)
    .digest("hex");

  return crypto.timingSafeEqual(
    Buffer.from(expected),
    Buffer.from(signature || "")
  );
}
A documentação genérica de Webhooks da Meta orienta gerar/verificar assinatura SHA-256 usando o payload e o App Secret. Capture e armazene os eventos importantes: não existe consulta histórica garantida de notificações webhook.
07

A regra que muda tudo: janela de 24 horas

Quando o usuário envia mensagem ou liga, abre uma customer service window de 24h. Nova interação reinicia o relógio.

🟢 Dentro da janela

Você pode enviar service messages livres: texto, mídia, contatos, listas, flows e outros tipos suportados.

🔒 Fora da janela

Você só pode iniciar/retomar a conversa usando template previamente aprovado.

A documentação também exige opt-in do usuário para receber mensagens da empresa. A janela de 24h não substitui consentimento.
08

Templates: mensagens aprovadas para fora da janela

Templates são ativos da WABA e passam por revisão. Categorias atuais: authentication, marketing e utility.

O que observar

  1. Templates são ativos da WABA.
  2. Precisam estar APPROVED para envio.
  3. Categoria, idioma e parâmetros fazem parte do contrato.

Nome

Até 512 caracteres; minúsculas, números e underscore. O mesmo nome pode existir em idiomas diferentes.

Variáveis

Podem ser nomeadas, como {{first_name}}, ou posicionais, como {{1}}.

Status

Só templates APPROVED podem ser enviados. Mudanças chegam por message_template_status_update.

Exemplo conceitual — envio de template aprovado
curl "https://graph.facebook.com/${GRAPH_API_VERSION}/${WHATSAPP_PHONE_NUMBER_ID}/messages" \
  -H "Authorization: Bearer ${WHATSAPP_ACCESS_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "messaging_product": "whatsapp",
    "to": "+55SEUNUMERO",
    "type": "template",
    "template": {
      "name": "seu_template_aprovado",
      "language": { "code": "pt_BR" }
    }
  }'
Limites e qualidade que valem conhecer

A documentação consultada informa até 100 criações de template por hora. WABAs de portfolio não verificado têm limite menor de templates, enquanto portfolios verificados podem ter capacidade maior sob condições. Qualidade baixa pode levar a pausa ou desativação.

09

Levar um número real para produção

Adicionar/verificar o número na conta não é o mesmo que registrá-lo para uso pela Cloud API. A documentação separa essas etapas.

O que observar

  1. Adicionar/verificar número não encerra o registro Cloud API.
  2. O status precisa estar connected.
  3. O registro exige PIN de verificação em duas etapas.

Requisitos importantes

  • Número válido capaz de receber verificação
  • Status connected para enviar/receber pela API
  • Display name
  • PIN de verificação em duas etapas obrigatório no registro

Teste → produção

O Get Started gera um número de teste automaticamente. Para o número comercial, use App Dashboard / Business Suite / WhatsApp Manager e complete o registro Cloud API conforme a documentação do seu fluxo.

Em portfolios novos, a documentação atual informa um limite inicial de números registrados; a capacidade pode aumentar conforme verificação e uso.

Avançado: Embedded Signup e coexistência

Para produtos SaaS/Tech Providers que conectam contas de terceiros, o Embedded Signup automatiza onboarding de WABAs e números.

O que observar

  1. É um fluxo avançado para onboarding de terceiros.
  2. Coexistência pode manter Business App + Cloud API.
  3. A documentação atual alerta para migração de versões antigas.
Atenção de versão: a página oficial consultada, atualizada em 26/06/2026, avisa que Embedded Signup v2 e v3 serão descontinuados em 15/10/2026. Integrações novas devem considerar o caminho v4.

Coexistência Business App + Cloud API

A Meta documenta um fluxo em que o mesmo número pode continuar no WhatsApp Business app e também usar Cloud API, com histórico sincronizado em cenários suportados.

Restrições específicas

No fluxo de coexistência documentado, há throughput fixo de 20 mps e uma janela operacional para sincronização após onboarding. Trate isso como arquitetura avançada, não como requisito do primeiro MVP.

!

Debug rápido

Os erros mais comuns parecem “API quebrada”, mas normalmente são estado, janela, token ou webhook.
Recebi HTTP 200, mas a mensagem não chegou

200/aceite da API não prova entrega. Procure o messages webhook de status e o WhatsApp Message ID.

Texto funciona às vezes e às vezes falha

Cheque se a customer service window de 24h ainda está aberta. Fora dela, use template aprovado.

Webhook não recebe nada

Confirme Callback URL pública HTTPS, Verify Token, assinatura do campo messages e logs do servidor. No test webhook oficial, a Meta orienta usar o botão Test no painel.

Template não envia

Verifique status APPROVED, idioma, nome exato, parâmetros e qualidade. Templates pausados/desativados não podem ser enviados.

Número adicionado mas API não envia

Verifique se o número foi realmente registrado para Cloud API e se o status está connected.
